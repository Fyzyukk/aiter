Task1：把 OPUS A16W16 的 Split-K workspace 交给 Torch 管理

流程：Python 解析 actual kid 和 split-K → 创建或复用 Torch workspace → C++ 校验参数 → 启动 exact-kid kernel。

以前

Python 仅完成部分选核，CSV miss 后由 C++ 继续选择 kernel。Split-K workspace 由 C++ 按 stream 管理，调用方不可直接控制，并需要额外 warmup。

现在

Python 一次解析最终 actual_kid 和 split-K，根据 kernel 注册信息确定 workspace 的 shape 和 dtype，并创建或复用 Torch Tensor。随后将 workspace pointer 传给 C++，workspace 生命周期由调用级 Tensor 管理。

任务和需求

  • 选 kernel 只能做一次，而且必须在申请 workspace 之前完成。
  • workspace 由 Torch 管理：默认自动创建，也允许调用方传入自己的 Tensor。
  • C++ 不再维护全局或按 stream 的 workspace，不再调用隐藏的 hipMalloc/hipFree。
  • workspace 的 shape 和 dtype 必须来自最终 kernel：gfx942/gfx950 two-stage、gfx1250 two-stage 和 fused 各用自己的真实布局。
  • generated C++ launcher 继续做最后一道安全检查，包括 device、dtype、连续性、对齐和容量。
  • HIP graph、非默认 stream、多 stream、BF16/FP32 output 和 bias 行为不能退化。
  • 生产路径使用 checked C ABI/ctypes；pybind raw 只留作兼容、测试和 A/B。
Python/JIT：选核、workspace 分配与调用入口 C++ kernel 启动、workspace 校验与 launcher 生成 Kernel 写入 workspace、Split-K 归并与结果输出 测试、benchmark 与文档 实际调用流程
