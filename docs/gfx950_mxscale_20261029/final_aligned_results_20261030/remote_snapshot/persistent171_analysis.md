# 171 个持续落后项：CPU 分组与现有 kernel 优化方向

本分析只读取同一份固定 gfx950/256 CU/128x128 CSV，未使用 GPU、未修改 kernel，也未改变 421 项的最终结果。171 项指历史 Opus 和本轮 Opus 都没有超过对应固定 CSV 的集合；另外 14 个新增回退项单独处理。

当前差距中位数 4.88%，历史同组中位数 5.57%；92 项已比历史 Opus 改善但仍输 CSV。135 项来自 Top8/101 次计时，36 项来自快速 Top4/11 次计时。82 项当前落后至少 5%，15 项至少 10%；117 项历史和当前都落后至少 3%。

四组共 108 项，占 171 项的 63.2%。当前赢家路线为 4wave 102、m-repeat 34、interleave 15、overlap 11、B-VGPR 9。pingpong_lds 就是 m-repeat JIT，不能重复计数。

## 三个优化方向

1. 大 M、长 K 优先现有 4wave。四个主组中的 72 项当前赢家为 4wave；大 M 的这条路线尤其集中。现有 panel16/32/64、PAD/non-PAD、wide/普通 12 个 CO 对主组代表 shape 已全部入选，继续加入相同候选没有新覆盖。固定最佳基础配置，优先研究加载、scale refill、等待与 MFMA 的交错排程，再做有限 GroupM0/4/8 对照。LDS/寄存器驻留与 VMEM 等待是待 profiling 验证方向，当前 CPU 表不能确认具体瓶颈。

2. 小 M、长 K 优先 interleave 与相关加载调度。N7168/K16384 的 M1216–1664 八项当前赢家为 interleave，约慢 11%–15%，历史也明显落后。代表项已经覆盖 BM128/192 和 WaveN2/4 四种几何，不能把持续差距简单归为这四种几何漏测。应检查 K 循环的 global→LDS、下一槽预取、barrier 与 operand 读取的顺序。该组来自 11 次快测，新增差距需统一口径确认。

3. 窄 N 的 B-VGPR/overlap 与 m-repeat 按已有路线对照。N768/1536/2048,K7168 合计 32 个持续落后项；窄 N 大 M 中 m-repeat 也经常是当前赢家。先固定赢家几何补齐少量参数对照，再优化 A fragment ring、B reuse 和 LDS/MFMA 排程。Top4 外的 seed 只保留精确赢家，不会展开同几何所有参数；因此 m-repeat 的参数遗漏尚不能完全排除。窄 N 不满足 GroupN16/32 的 N/BN>=256 条件，扩大这些参数没有依据。B-VGPR/overlap 应比较实际 B_AHEAD 与 publish 位置，避免把被裁剪为相同距离的 BD1/2 当独立改进。

小于 1% 的 13 项以及快速轮次中新扩大的差距，先做少量统一口径复核。优先修改已有明显、长期差距的路线，一次覆盖同组多个 shape。CPU 可以完成源码、ISA/资源分析和候选设计；真实瓶颈及性能收益需要后续明确使用 GPU 时验证。
