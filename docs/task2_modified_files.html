Task2：将 OPUS GEMM 拆成四类明确接口

统一 Python、pybind、C++ 和 generated launcher 的参数与路由。A16W16 只启动 Python 已确定的 kid；三种 A8W8 计算分别使用自己的接口、注册表和输入检查。

以前

generic opus_gemm、旧 tune 入口和 C++ shape heuristic 同时存在。A8W8 的 no-scale、plain blockscale 和 bpreshuffle 合同没有完全分开，scale 还可以缺省。

现在

四条 launch 接口分别接收固定参数。C++ 按当前 GPU 架构、输出类型和已确定的 kid 查表启动；旧 C++ tune、generic 路由和 C++ runtime heuristic 已删除。

原始需求与完成情况

原始要求集中在四件事：gfx950 接入统一路径、删除 Python/C++ 重复选核、缩小 C++ 职责，以及整理 dtype/layout 接口。当前代码均已完成。

最终接口与约束

  • 提供 opus_gemm_a16w16_launch()、opus_gemm_a8w8_launch()、opus_gemm_a8w8_blockscale_launch() 和 opus_gemm_a8w8_blockscale_bpreshuffle_launch() 四条统一接口。
  • A16W16 的 shape、CSV 和 heuristic 选择只在 Python 完成；C++ 不再根据 shape 选择另一个 kid。
  • 三种 A8W8 接口分别定义参数、scale、WQ 表示和输出类型；两个 blockscale scale 都是必选 Tensor。
  • kernel 注册按 GPU 架构、接口类型、kid 和输出类型查询，禁止跨架构、跨接口类型或跨输出类型复用相同数字 kid。
  • 即使某个架构当前没有对应 A8W8 kernel，公开函数仍存在，并在调用时明确报告没有可用 kernel。
  • CSV、compiled-kids sidecar、Python heuristic 默认 kid 和 mandatory A8 kid 继续进入 subset compile，保证运行时可选 kid 已编译。
  • 仓内生产调用方和 tuner 改用新接口；旧 Python tune 名仅保留 warning 和参数转发。
