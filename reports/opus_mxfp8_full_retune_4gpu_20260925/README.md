# 9010/9011/9012 更新后的四卡全量复测

状态：已完成。全量扫描、17 项五轮确认及 295 项选择回放全部通过。最终 OPUS 208 胜 / 87 负，详见 [RESULTS.md](RESULTS.md)。

本轮重新测量原模型目录中 M≥1024 的全部 295 个受支持 shape，共 27,690 个候选配置。原目录另有 10 个 shape 超出现有有符号 32 位 tensor 字节寻址范围，见 `deferred_shapes.csv`。

按 (N,K,M) 排序后轮流分片；每个 shape 的全部候选和三轮计时均在同一张卡上进行。每个进程用 ROCr UUID 绑定，并核验 PCI 地址、gfx950 架构和 256 CU。ROCr 数字编号与物理卡编号不一致，不能直接用数字 4–7 绑定。

候选范围：CK 5,310、CKTile 9,735、ASM 11,370、OPUS 1,275。OPUS 包含全部已注册的 9000、9010、9011、9012、9020；ASM 包含全部合法 split-K 分区，CKTile 包含全部 BlockPerCu 配置。

每个候选先检查正确性，合格后计时三轮，每轮 warmup=5、iters=51；使用原 `run_perftest` profiler 和自动输入轮换。候选顺序随轮次轮换。最终时间为三轮中位数；数值不合格的候选保留失败记录，不参与选优。数值标准沿用 FP32 累加参考的逐元素区间：`1e-4 + 5e-5 * sum(abs(A_i*B_i))`，区间端点舍入到 BF16，要求零超界元素。

公共输入准备、B preshuffle、scale 解码及参考计算不计时；后端内部转换计时，CPU launch 开销不计时。各 shape/轮次之间检查指定 GPU 的空闲状态。所有进程复用同一套冻结二进制，测量期间禁止编译，并在开始/结束核对源码与二进制哈希。

新 pipeline 的适配、源码快照和构建记录位于 [上一目录](../opus_mxfp8_full_retune_20260925/README.md)，二进制为 `../opus_mxfp8_full_retune_20260925/jit_03/`。实际配置为 9010=S3/K+2、9011=S3/K+2、9012=S4/K+3，直接输出 BF16。三个打包 B scale 的 LDS 区域均按 uint32 宽度扩为 256 字节。185 项测试已通过（99 GPU、86 CPU/接口）。

上一目录的单卡扫描按用户要求中止；其部分计时不参与本轮结果。旧 206 胜/89 负记录只用于对照状态变化。

完成四个分片后，`merge.py` 验证覆盖无遗漏、无重复、来源一致，再合并为 `full_r3_*`，保留每行物理 GPU 和 UUID。`summarize.py` 独立核对全部候选身份、数值状态和中位数，导出比较表、剩余清单以及原生 E8M0 tuner 的 13 列选择 CSV。这些选择文件使用原生 E8M0 scale 接口。
