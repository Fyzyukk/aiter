# OPUS 落后 FlyDSL 的 294 项清单与下一轮优化

当前 693 个全后端 OPUS 赢家中，按保存的历史 CSV 对比最快可用 FlyDSL 路径，399 快、294 慢。
本目录保存所有294项、当前公开ID和解析后的实际实现、对手tile/splitK/prefetch，以及独立实验计划。
GPU 测试已按用户要求停止；本次只有 CPU 数据分析、源码准备和隔离离线编译。

**可以继续优化，但不能承诺每个 shape 都超过 FlyDSL。** 294项全部已经是本轮13,027个合法OPUS配置中的最快项；
现有候选简单重选没有隐藏的胜出配置。需要新增机制/几何，或在有局部实证时调整编译器。
同卡复测仍未完成，10月9日受外部占用影响的smoke时间不参与本文。

## 完整清单

- [losers294.csv](losers294.csv)：每项M/N/K、公开ID、实际ID/fixedK、tile/wave/global splitK、双方时间和需要降低的延迟比例。
- [by_actual.csv](by_actual.csv)：实际实现分组；[by_parent.csv](by_parent.csv)：公开ID分组。
- [by_nk.csv](by_nk.csv)：固定N/K的全部M成员；本文下方也列出完整成员。
- [experiment_plan.json](experiment_plan.json)：独立候选、代表shape、风险和验收条件。
- [shortk9022/README.md](shortk9022/README.md)：已实现并完成离线编译和CPU检查的第一组短K原型。

CSV的wave_M/N/K表示workgroup内的wave分工，mxpsh的`flydsl_waves_per_eu`单独保存编译器occupancy提示，
不能把名称中的w0/w2/w4当成workgroup wave数。没有等价单值定义的pipeline字段保留为空。

历史落后比例 `(OPUS_us/FlyDSL_us-1)*100%` 和需要降低的延迟比例 `1-FlyDSL_us/OPUS_us` 不同。
例如16×768×7168慢47.97%，意味着OPUS需要减少32.42%的延迟才能追平；不是要降低47.97%。

## 优先做的改动

1. **actual9070的Clang24独立对照，3项。** 已有同候选六轮证据：112×768×7168、16×6144×7168、16×7168×7168，
   Clang23分别慢11.87%/13.99%/16.06%。对应实际延迟可减少约10.61%/12.27%/13.84%，尚不能据此声称超过FlyDSL。
   不全局切换工具链，不把局部测量乘进历史表。
2. **9022 fixed K384/K768与几何改进，72项，其中短K28项。** 当前160×128 runtime、panel32、两次SFA pass；
   第一原型保持tile/ring/scale数学，fixed3/6步并用panel8/一pass。下一步BM96/64和A-LDS/B-register独立队列，
   72项对手47项有direct-B。672×7168×384当前tile计算800行，BM96可计算672行；这提供几何线索，不证明性能收益。
3. **small K分工，32项（9041/9052）。** 31项对手用K256/512软件stage、13项用global splitK>1。
   当前8个local-K wave和LDS归约可试较少wave+global split4；之后再做A-LDS/B-register的真实K256/512stage，
   每次K128 scaled-MFMA仍需其自身scale。当前register已直接加载A/B，仅把队列改名K256没有新机制。
4. **small/LDS独立B预取，73项。** 实际9044/9056/9046/9047/9055，35项对手direct-B。先保持A-LDS、几何、
   scale/output/split，仅将B LDS往返改成独立VGPR队列；ahead1/2/3和1×4 wave排列分别做实验。
   风险是M wave间B读取重复和VGPR增长。
5. **窄N的fine/splitK，14项。** N768/K7168下9062/9063有14项落后，13项对手split1/direct-B。
   试BM48/64×BN64/128、较少wave、split1/2，完整计入producer+reducer成本；不重新使用已淘汰的固定M80/K16384 BN64。
6. **9030大输出，10项全部K1536。** 九项N65536，历史差距13.11–34.62%。fixed1536/panel16仅减少静态资源；
   更实质方案是A-only3stage+directB，并把C输出分成两批96行，或128×256/4wave新geometry。
   当前完整C staging需101,376B，直接删除B LDS仍不能降到80KiB；分块后79,168B main/50,688B Cchunk才有静态资源余量。
   64位C寻址、每tile资源边界和signed精度必须保持，静态资源余量不等于动态occupancy已提高。

以上范围相互重叠，不能相加为预测胜出项数。
9021保留已采用的scale调度；9024六项先统一复测协议，因历史19µs与后续同候选14–15µs有明显计时差。
9000/9001的12项只输compact mxpsh，原raw BMM对比均快；需要明确调用方是否已有compact A-scale。

## 比较范围与后续验收

本294项只涉及当前全后端表选择OPUS的693项。若目标是让**全部745项都由OPUS超过FlyDSL**，
另52项当前选CK/CKTile/ASM也要包括；纯OPUS745项历史对比为411快/334慢，
其中额外52项中40项OPUS也落后。最终应该以745项完整OPUS集合和FlyDSL同卡输入对照验收。

当前没有干净的完整OPUS/FlyDSL同卡结果。GPU恢复后先signed/reference/边界guard/split重复调用检查，
每shape同卡共享输入池五轮正反序完整调用；原399胜项和全部745项回归通过后才发布新选型。
所有新候选用独立未注册ID/库，baseline、正式CSV和已有raw保持。
