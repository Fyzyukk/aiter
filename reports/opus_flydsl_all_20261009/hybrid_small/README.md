# Small LDS: A stays in LDS, B feeds MFMA from an independent VGPR queue

Eight actual implementations now have concrete private direct-B kernels and successful offline Clang23 compile/link results. They cover **85 historical losing shapes**, seven public parent IDs, and 255 legal shape/candidate pairs. Each shape has ahead1, ahead2, and ahead3 variants. GPU testing remains stopped: no numerical or timing result is claimed, and every prototype remains unregistered.

The initial 73-shape group (actual9044/9056/9046/9047/9055) was extended to actual9043/9045/9049. The frozen baseline uses the current small-LDS pipeline and traits; it is independently rebuilt with the same compiler flags. The historical formal library is hashed read-only and never loaded. Current rebuilt baseline machine code is not asserted to equal historical machine code.

The new [pipeline](candidate/pipeline.cuh) removes all B matrix LDS allocation, global-to-LDS copies, and LDS reads. Each wave loads its own B MFMA fragments from the raw standard N16/K16 preshuffle into a compile-time VGPR ring. For fragment `n`, its N16 group is `(n*T_N + wn)*16`; its two 16-byte parts come from `nr*stride_b + lane*16 + kt*2048` and the same address plus 1024. The ring contains `Ahead+1` slots. A retains each family's tile, wave layout, XOR mapping, and original LDS stage count. Native E8M0 SFA/SFB addressing, scale packing, FP32 accumulation, splitK=1, output2 packed stores, output1 C staging, and reducer source remain preserved.

The two queues have separate sizes. Their common ring period gives compile-time indices without dynamically indexing VGPR arrays. A slot and its register scales are reused only after all waves complete their LDS reads and cross a barrier; the current B fragment is copied out before its slot is refilled. Each K step uses conservative VMEM/LDS completion and two workgroup barriers. This changes the original clustered A synchronization schedule and may sacrifice overlap; wait-count and barrier refinements require later GPU validation. The existing A `PREFETCH_BEFORE_READ`, `CLUSTER`, and `READ_ONLY_DRAIN` traits do not select the private schedule.

The [private traits](candidate/traits.cuh) keep the original A stage sizes and place LDS scales immediately after A. For output1, `lds_bytes(k)` takes the maximum of A+scale allocation and full C staging so deleting B cannot make a short-K C buffer too small. Every covered shape stays within 160 KiB. LDS here is dynamic: ELF fixed group segment is zero for all kernels; the launcher allocation must be included when comparing resources.

All 32 kernels report zero scratch, VGPR spills, and SGPR spills. Complete SGPR, symbol/ISA size/hash, device ELF hash, and compiler disassembly arguments are in [cpu_audit.json](cpu_audit.json). The 1×4 families read B once per workgroup logical fragment; 2×2 families duplicate B reads twice across M waves; 9046 duplicates them four times. Larger VGPR queues can reduce occupancy or create later spills. Neither lower LDS allocation nor spill-free static metadata proves improved occupancy or latency. Ahead2 can also enlarge instruction footprint because its ring period is the least common multiple of A stages and three B slots.

The CPU checks use byte-identical expressions from frozen OPUS layout helpers, with only host attributes adapted in a separate audit include. The successful host-audit source is [layout_guard_check.cpp](layout_guard_check.cpp); its [binary](cpu_audit_v4/layout_guard_check) has no HIP or ROCR dynamic dependency. It verifies 2,424,832 A/B address bytes across K128/384/768/1024/1536/3072/7168/16384, including XOR producer/consumer addressing and exact B LDS-to-direct equivalence. It also checks 198,144 queue consumptions for all 128 possible loop lengths and three depths, 103,961,600 scale consumptions including arbitrary M tails, output coverage, byte-identical output/reducer source, LDS allocation bounds, and actual launcher guards. These CPU checks do not model GPU instruction scheduling or prove numerical correctness.

The [coverage CSV](candidate_coverage.csv) and [coverage JSON](candidate_coverage.json) list every historical shape against all three variants, with geometry, scales, split, dynamic LDS, compiled VGPR/SGPR/scratch, legal status, and explicit stopped-GPU validation fields. The [source manifest](source_manifest.json) freezes 84 dependency files and read-only control hashes. [build_receipt.json](build_receipt.json) records exact compile/link argv, compiler identity/SHA, all source SHAs, objects/libraries/log hashes, return codes, and elapsed build time. The [final manifest](final_manifest.json) hashes all private artifacts.

Two earlier host-audit setup attempts are retained in [audit_attempts.json](audit_attempts.json): a HIP host-only direct link was rejected by a CPU ELF dependency check before execution, then an impossible test K tile for stride7168 triggered a host assertion. The final attempt compiles a host-only object, links through ordinary clang++, and tests only tiles inside each stride. No HIP library was loaded or executed by the audits.

Reproduction is CPU-only and refuses to overwrite prior outputs: `python3 prepare.py`, `python3 build.py`, then `python3 audit.py --output-name cpu_audit_v4` in a fresh copy of this private directory. A fresh audit directory is required. GPU numerical validation, signed/reference checks, guards under actual execution, and same-input full-call timing remain pending until the user restores GPU testing.

Independent read-only review of the neighboring main-family prototypes identified and verified a correction to their launcher SFA descriptor bounds. The final [fix review](main_variants_review_fix.json) binds the corrected source hashes, both final library hashes, and all 32 main/pin kernel resource records; all show zero scratch and spills. Its [additional host audit receipt](main_deep_cpu_v1/receipt.json) records 1,966,080 A/B matrix address checks for BM64/96/128/160 across eight K strides, 913,408 pin SFA consumer bytes through the symbolic DPP/perm transpose, and 228,352 pin SFB consumer bytes. Panel16/32/64 lane guards, consumed producer uniqueness, K-tail descriptor bounds, and reset variants pass. This audit also compiles a host-only object and links without HIP/HSA before execution. The earlier [review](main_variants_review.json) remains as a superseded finding record.
