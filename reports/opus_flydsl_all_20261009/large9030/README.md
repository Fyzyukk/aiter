The private 9030 direct-B pipeline compiles and passes the corrected CPU layout/resource audit. It uses 79,168 bytes of LDS and 170 VGPRs with zero scratch or spills. Numerical and performance validation remain unrun because GPU work is stopped. All variants are private and unregistered.

Three independent libraries are retained in `build_v2/`: the current frozen runtime control, a fixed-K1536/panel16 control, and the direct-B candidate. The fixed-panel control retains the original two A/B LDS stages and BF16 output shuffle. It changes the resident scale capacity from 128 to 16 K128 columns and fixes the loop count at twelve. The shortened SFA layout spans more producer rows than the 192-row tile, so inactive producer rows are guarded. Only twelve scale columns are consumed. The current runtime already guards inactive K columns; reducing panel capacity alone does not reduce the active scale bytes fetched.

The direct-B candidate retains the 192×256×128 tile, eight waves, native E8M0 scale contract and swapped-operand scaled MFMA. B bypasses LDS and uses two single MFMA fragment registers, carrying the N-fragment queue across K tiles. Each fragment is consumed by all three M repeats before the pending next fragment is copied and its register is refilled. A uses three 25,344-byte LDS stages. Explicit completion and block barriers publish future A copies and retire A readers. The matrix arena becomes a 96-row BF16 C buffer after matrix reads complete; two output chunks each use 50,688 bytes and six cooperative writeback passes. Each chunk's LDS readers retire before the arena is overwritten.

LDS drops by 64,192 bytes from the local runtime control. The emitted 79,168-byte footprint fits an 80 KiB budget, but this is only a static prerequisite: 170 VGPRs, eight waves, duplicated B reads across M waves, conservative waits and chunk output synchronization still require measurement. No occupancy, bandwidth or speedup claim follows from this metadata. This pipeline changes data movement and output staging; it does not repeat the previously rejected 9030 midpoint experiment.

The audit-only OPUS header exposes the actual layout/MMA adaptor methods through host attributes; its diff changes attributes only. The device compile uses the unchanged frozen header.

The final host executable checks:

- The actual frozen A and B global producers, LDS addresses and MFMA fragment readers, including padding and lane offsets. Every matrix byte has one producer. The direct-B address expression is extracted from the candidate and agrees byte-for-byte with the frozen B staging/read path for every wave, lane, N repeat, fragment half and all twelve K128 tiles.
- Panel16 SFA producer once-coverage, consumer M repeats, identity tail bytes, and both compact SFB halves. The 64-, 128- and 192-row final tiles are covered.
- The actual `make_tiled_mma` and `partition_layout_c` mapping. Every BF16 cell has one producer and one writeback in the two chunk96 arenas; four-element fragments stay within a row and chunk.
- The A3 ring and two-fragment B queue sequence, source completion/barrier fragments, all ten historical K1536 shape guards, two runtime nonwinner K controls, large C bases beyond signed32, bounded per-tile output resources, and legal/rejected input-byte boundaries. Synthetic pointer values are never dereferenced.

The raw private ABI is `launch(9030, a, b, sfa, sfb, c, m, n, k, stream)`. It requires positive M divisible by 64, N divisible by 256, K divisible by 128, contiguous FP8/native E8M0/BF16 buffers, standard N16/K16 B preshuffle, signed32 A/B byte extents and per-tile C spans. Total C must exceed signed32 and fit signed64. The candidates accept only K1536; the local runtime control accepts the existing K range. C uses a signed64 tile base and bounded resource; batch is one and `stride_c_batch` is zero to avoid narrowing the full C element count. A/B/SFA/C require 16-byte alignment; SFB keeps byte alignment. Buffer ownership and nonoverlap are caller responsibilities.
